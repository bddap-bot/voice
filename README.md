# voice

The phone page at <https://bddap-bot.github.io/voice/> sleeps between conversations with its microphone open, listening only for its wake phrase; while it sleeps no audio leaves the page and no Live session is open. `docs/identity.js` holds the name the live model is given, the wake phrase, the sign-off sentence, and how long a session may pass without speech before it ends. The wake phrase, or a tap on the puppet, opens a Live WebRTC session through the voice relay. The page's offer carries the identity, with the name and the sign-off, and the action instructions as the session's instructions; once the session starts, the page tells it on the commentary channel that it was just woken, so it greets. Every later session on the same page also starts with a memory of the page's latest earlier conversations, up to 8 KiB: their transcripts, oldest first, each marked with how long ago it ended, then a note that the model has just been woken. The model decides when a conversation is over, from a request to sleep or an implied close such as a goodbye, and ends its reply with the sign-off. When the live output transcript contains the sign-off, the page closes the session once playback goes quiet; a tap, the idle limit, or the relay reporting the call closed also end it. Muting the microphone holds across sessions. The elapsed clock is visible while a session is open. There is no legacy fallback: when the relay cannot open a session, the one page fails closed and says the conversation could not start.

The spotter follows openWakeWord: its melspectrogram and speech-embedding models (v0.5.1, Apache-2.0, in `docs/wake/`) run with onnxruntime-web in a worker that an audio worklet feeds 80 ms chunks, and a one-hidden-layer classifier trained for the phrase scores every chunk. A score over the model's threshold wakes the page; an episode that approaches the threshold without crossing it is logged as a `wake-miss` session event. The page asks the backend for its model with a `wake-model` relay frame; without a valid model for the configured phrase it reports a page error and does not listen, while a tap still opens a session. The backend keeps its model in private state.

The page draws the puppet at most 60 frames a second, whatever the display's rate, and at most 15 while it rests asleep in an idle; its easing is timed in seconds, so it moves at the same speed at either rate. Hidden, it draws nothing. The audio worklet hands each chunk to the spotter's worker over its own message channel, so the main thread runs no code for audio. The page keeps listening while hidden: a hidden page still wakes on its phrase for as long as the browser and the operating system keep its microphone and worker running. On Android a web page cannot keep the microphone once hidden; the Android app in `docs/android.md` keeps it.

`npm run idle-cost` measures the asleep, visible page in headless Chromium: the real puppet runtime draws the synthetic figure from `vr/golden/` in its sitting idle, and the real spotter listens to the fake microphone, each alone and together. It samples each thread's CPU time and voluntary context switches (wakes) from `/proc` over 20 seconds. WebGL renders on SwiftShader, so the GPU process's CPU time stands in for GPU time. `-- --phrase` instead plays the golden wake clip into the same page and exits once the page wakes. With both running, in milliseconds of CPU per second, before and after the frame cap and the worklet's channel:

| asleep, visible | frames/s | main thread | wake worker | audio threads | GPU process, SwiftShader (per frame) | all page processes |
| --- | --- | --- | --- | --- | --- | --- |
| full-rate drawing, chunks relayed by the main thread | 59.8 | 76 ms, 176 wakes/s | 87 ms | 53 ms | 4305 ms (72 ms) | 4588 ms |
| capped drawing, chunks sent straight to the worker | 15.0 | 35 ms, 141 wakes/s | 91 ms | 49 ms | 1117 ms (74 ms) | 1336 ms |

The worker and audio columns differ between the rows only by run-to-run noise. With the spotter alone, the main thread spent 4 ms and woke 20 times a second before the change, and now spends 0 ms and wakes 4 times. The worker's 90 ms a second is the two model runs per 80 ms chunk; running two chunks per call saved under a tenth of it and would delay every wake by 80 ms. Drawing is the idle page's main cost, and it scales with the frame rate.

`node scripts/wake.mjs train [--phrase <text>] [--out <file>]`, run under `nix-shell -p piper-tts espeak-ng flite ffmpeg`, rebuilds a model, by default `scripts/wake-demo.json`. It synthesizes the phrase with Piper (four multi-speaker and fourteen single-speaker voices), espeak-ng and flite, adds synthetic room reverberation and noise, and trains against LibriSpeech dev-clean, generated near misses, Harvard sentences and noise. It takes the lowest threshold that holds validation audio, including half of openWakeWord's false-positive validation features, under 0.25 false accepts per hour, then writes into the model file the recall on held-out voices, speakers and speeds and the false accepts per hour on held-out audio: LibriSpeech test-clean, the other half of those features, and Harvard sentences and near misses in held-out voices. The voice models, LibriSpeech archives and validation features are checked against SHA-256 digests, and downloads are cached under `node_modules/.cache/wake`. `--acav <megabytes>` adds that much of openWakeWord's ACAV100M features as negatives; they are licensed CC BY-NC-SA 4.0, so such a model must be written outside the repository. Without them, the demo model false-accepts about 35 times an hour on the held-out validation features; it is a fixture for the tests, not a model to deploy. Recordings are optional: `node scripts/wake.mjs ingest <clips> --corpus <dir> --phrase <text>`, or `--ordinary` for speech without the phrase, groups clips into sessions by time and holds the latest quarter of the sessions, at least one, out for evaluation. One voice note repeating the phrase about ten times makes a session. `train --corpus <dir> --out <file>` adds those recordings, keeps their decoded audio and features under `<dir>/cache`, and refuses to write the model inside the repository.

**Learn my voice**, on the expanded controls card, makes a voiceprint between conversations: talk normally for about ten seconds while the button shows progress; tapping it again stops. The page keeps only the mean of 192-number speaker embeddings from 3D-Speaker's ERes2Net model (trained on VoxCeleb, Apache-2.0), computed in the browser and kept in its local storage; the learning audio is neither sent nor stored. In later conversations the microphone passes through this filter before the Live session. **Voice ID on**, on the card once a voice is learned, switches the filter off and on, also during a conversation; off sends the microphone itself, with no added delay, and keeps the voiceprint. The choice stays on the device with the voiceprint; learning a voice turns it on, and forgetting the voice stops filtering at once. Speech is held from its start and scored after about a second; matching speech is sent from its first sound, so no word is clipped, but it arrives about a second late plus scoring time, and each reply starts that much later. Other speech is dropped. Sent speech is rescored every second, so a different voice that follows without a pause is cut off within about two seconds. The filter tells voices apart but does not authenticate: a similar voice or a recording gets through. The model, about 26 MB, is fetched from a pinned revision on first use, checked against its SHA-256 digest, and cached. If it fails, learning stops without a voiceprint, or the conversation continues unfiltered with the status "speaker filter off, hearing everyone"; the next conversation tries again. Without a voiceprint, after **Forget my voice** or **Forget token**, or after the pinned model changes, the next conversation sends everything it hears. The idle limit counts only speech that was sent. The session's microphone recording, described below, still holds everything the microphone heard, and each score is logged as a `speaker-score` session event with its time span. `nix-shell -p ffmpeg --run 'node scripts/speaker-print.mjs --model <onnx> --out <file> <recording>...'` makes a voiceprint file in the overlay's format, described below, from many recordings of the user's own conversations, such as the server's session microphone recordings, instead of ten seconds of learning: it embeds every mostly-speech window and keeps the voice most recordings share, each recording weighing the same however long it runs, so a long recording dominated by a television or other people does not outvote the user's own conversations. Only recordings whose main speaker is the user belong in it; a voice that dominates them is accepted.

The page's server, `voice-web`, is not part of this repository and is not published. The page reaches it over iroh with ALPN `voice-web/1`, and its `voice-web token` command prints the device credential the page asks for. The page's iroh transport in `docs/relay/` is a copy of the bddap-bot/botq browser build at commit `3868c6d` (iroh 1.0.3); updating it replaces both files. The server relays the browser's SDP offer, with its instructions and, for a woken session, the earlier turns and wake marker, to a codex app-server realtime session and returns the SDP answer; it sends a `closed` frame with the reason when the call ends, and ends the call itself at its deadline or when the page disconnects. Credentials stay on the server: they never enter the browser, repository, relay diagnostics, or logs. There is no per-minute bill for Live audio.

Live speaks the realtime v3 data-channel dialect. The page reads `session.started`, `delegation.created`, `input_transcript.added`, `output_transcript.added`, and `session.usage.updated`, whose audio duration it logs and whose usage limit, when set, it reports to the server once per conversation in a `usage-limit` frame. It sends only context appends: `session.context.append` on the `speakable` channel for words to say, `commentary` for notices the model may mention, or `developer` for silent direction, and `delegation.context.append` for speakable text answering a delegation. The server closes the call on any client event it rejects, so `checkedClientEvent` in `docs/live.js` refuses every other shape before it is sent.

Browser errors and session lifecycle events travel in batches over that authenticated relay into telemetry. A Live call that ends without the client asking, closed by the provider, by its own connection or by a lost relay, before or after it opened, is reported as an error by the page or overlay that held it, sent once the relay is back; only a client still running can tell a dropped call from one it walked away from. The `live-config-*` session records capture only provider-reported model IDs, delegation type/target/model, and tool names from session and delegation events and the SDP answer; absent fields remain absent, and instructions and transcript text are excluded from these configuration records. The complete user/model transcript and separate microphone/model Opus-in-WebM streams are stored per session in private server state through acknowledged, retrying, size-capped uploads.

Client delegation makes the backend agent the hub. The model emits `delegation.created`; the page sends the exact `input_transcript.added` text heard since the previous delegation, plus up to 20 earlier visible turns, to the server, which emits a `voice-note: web ... request <id>` hub event containing an `utterance` and `context` JSON object. A hub reply is text to speak; the page appends it as speakable context in a `delegation.context.append` naming the delegation item. While a delegation awaits its reply, if the model neither speaks nor delegates within three seconds of the latest user transcript text, the page itself delegates the text heard since the previous delegation, and the hub's reply or failure is appended as speakable `session.context.append`, outside any delegation. The user can mark the end of a request with the hand-off phrase, `HAND_OFF_PHRASE` in `docs/identity.js`: text since the previous delegation that ends with it sends, without the phrase, every user turn since the previous request so ended or the last sleep, so a request the model delegated in pieces also reaches the hub whole; the page delegates it itself if the model has not within three seconds, even if the model spoke. Every other hand-off, whether the model delegated or the turn went unanswered, waits until the speech sounds finished: a worker runs [Smart Turn v3.2](https://huggingface.co/pipecat-ai/smart-turn-v3) (BSD-2-Clause, the float export pinned by `TURN` in `docs/turn.js`) with onnxruntime-web on the newest eight seconds of the microphone audio Live hears, and a probability of at least `TURN.complete` hands off at once. Otherwise the hand-off waits; more speech joins it, under the model's newest delegation, and is judged again after `TURN.quietMs` of quiet, and `TURN.holdMs` of quiet after the last word hands it off anyway. A judge that cannot run lets every pause end a thought. Each judgement is logged as a `turn-verdict` session event with its probability and time. The page appends a reply as soon as it arrives, even while the user is still speaking; the model speaks it at its next turn, after the user finishes, as it would answer anything else it hears. Each append holds at most 500 tokens, so longer text arrives as several appends; a reply reaches the model if the session is still open and the model has not signed off. The hub may send several replies to one request, such as a status and then its result, or a series of slides. A later reply waits while the model is still speaking an earlier hub reply; once that reply is spoken and playback has been quiet for 1.5 seconds, the next is appended and its display item appears. If the user speaks while the model is speaking a hub reply, the later replies still waiting are dropped, each logged as a `hub-reply-dropped` session event. A spoken reply that reaches the page while Live is asleep is acknowledged as unspoken, so the hub learns it was not heard. An answer to a question in a hub reply is delegated without being asked; a change of subject is handled as a new request. A request to sleep is never delegated: the model signs off even while a delegation awaits its reply. When a session ends for any reason, words heard since the last delegation go to the server once in an `ended` frame, which it emits as a hub event marked `session_ended`, since no voice is left to answer it. Each delegated turn is also traced: the page sends one OTLP span per stage (`hear`, `decide`, `delegate`, `await-speech`) in a `spans` frame, and the delegation request carries its `delegate` span as a W3C `traceparent` so the server's stages join the trace. A turn the model answers without delegating is traced as `hear` and `reply`.

A turn's `reply` span runs from the last transcribed speech to the start of reply audio. Each avatar load is also traced in the `spans` frame: an `avatar-load` span carrying `avatar.file` and `user_agent.original`, with one child span per stage — `bytes` (transfer or cache read, with `puppet.bytes`), `parse`, `select`, `fit`, `render` (the first GPU-completed frame), `clips` (the remaining wait for clip motions, fetched once per page alongside the first model) and `animate`; the avatar catalog is fetched once per connection, not per load. The server exports page spans as OTLP with resource `service.name=page` and `host.name=voice` (a fixed label). Its collector's file exporter writes OTLP-JSON lines grouped by `host.name`, so page spans land in `otlp-voice.jsonl` in the collector's output directory. From that directory, this prints per-stage p50/p90 milliseconds over completed loads, by device class (phone, tablet, tv or desktop, from `user_agent.original`):

```sh
jq -rn -f scripts/avatar-load.jq otlp-voice.jsonl*
```

A hub reply may also carry standing instructions: how the model should behave from then on, such as how to fill a wait. Appended beside a reply, instructions cut off its speech, so the page waits until the reply is spoken, playback has been quiet for 1.5 seconds, and no other hub reply is waiting; then it sends them as their own `session.context.append` on the developer channel, which changes behavior without being spoken. A reply of instructions alone ends the delegation's wait silently. After every 10 minutes of session audio since they were last applied, as reported by `session.usage.updated`, the page appends the latest standing instructions again, so they stay in force through a long session. The server puts them in the startup instructions of later sessions.

At each session start, the server may append a situation card of current context, under 600 words, to that session's instructions. Small questions plainly covered by the card may be answered directly. Projects, machines, schedules, plans, facts, or current state beyond it delegate by default.

The authenticated page loads its VRM puppet catalog through the iroh connection. The page fetches the active avatar as soon as it connects and shows it seated and asleep; other avatars are fetched only when chosen in the appearance selector. Wake detection and signalling do not wait for the avatar to load. Until it appears, the stage shows a tap-to-talk prompt. Models remain on the server and are cached only in the authenticated browser. A tap on the rendered puppet wakes it or puts it to sleep: it sits with its eyes closed while asleep, stands and listens while Live is open, and sits down asleep again when Live closes. While Live is open, the page keeps the screen on with a Screen Wake Lock where the browser supports it, and takes the lock again when the page returns from the background; asleep, it holds none and the device's screen timeout applies. Appearance selection is persisted on the server, and required credit appears below the puppet.

Completed output sentences are classified locally into gestures and moods with quantized MiniLM embeddings. Model setup prefers WebGPU and retries with WebAssembly. On the checked-in 50-line hand-labelled evaluation set, the former keyword mood rules score 2/50 (4%) and the embedding centroids score 40/50 (80%). Run `node test/action-evaluation.js` to reproduce the comparison. Asking Live to mark its own actions with bracketed tokens instead was measured over 59 sessions and dropped: it annotated 7% of sentences ([#29](https://github.com/bddap-bot/voice/issues/29)).

The adjacent share box accepts text, URLs, and one PNG, JPEG, GIF, or WebP image up to 8 MiB. The authenticated relay checks the image bytes, saves an accepted file in private state, and emits a `voice-note` hub event with the text and attachment path. An open Live session receives a short arrival notice.

Beside the puppet, the single page keeps a live delegation log: every turn as the model heard it; the exact hub request, reply, and round-trip timing when delegated, or a visible “model alone” tag; and the exact output transcript the model spoke. The session's audio duration is logged on close. This is observability, not a second interaction surface.

A phone may discard the page while it is in the background and reload it when the user returns. While the page is hidden, including as it unloads, its tab's session storage holds the delegation log, about the newest quarter million characters, and whether Live was open; the copy is deleted whenever the page is in view. On reload the log reappears and remains the memory of earlier conversations; a conversation that was open is marked ended at the last save. If Live was open and less than the idle limit has passed since that save, it opens a new session once reconnected. The display panel and usage lines are not kept, and nothing survives a crash while the page is in view or closing the app.

Hub replies can add markdown, a tappable link, an image, or an HTML document to the adjacent display panel; a reply may carry only a display item. New items appear first, and image bytes travel inside the reply, only over the authenticated relay connection. Every link in the panel opens in a new tab, so following one never takes the page, and its Live call, away; leaving the page mid-call cancels the call, and a reload resumes it. The markdown autolinks bare URLs and renders three block kinds client-side: a ```mermaid fence as a diagram, TeX between `$…$` or `$$…$$` through KaTeX, and a ```chart fence through Chart.js, whose body is either a Chart.js configuration as JSON or CSV with a header row and one label column followed by numeric series, with `chart bar` or `chart scatter` selecting the kind. An HTML document stands alone, with nothing around it, and runs in a frame the size of the panel: `docs/frame.html`, loaded in an `<iframe sandbox="allow-scripts">`, so it has an opaque origin and cannot reach the page, its storage, cookies or relay, open popups, submit forms or navigate the page; a link in it navigates only the frame. The page hands the document over by message and the frame writes it under the frame's own policy, which the document can only narrow: inline scripts and styles, data and blob URLs, and scripts, styles, fonts and images from cdn.jsdelivr.net, unpkg.com and cdnjs.cloudflare.com, with no other connection; the page's `frame-src 'self'` keeps the frame from navigating to another origin. While it is the newest item the panel holds only the frame; the next item removes it. The VR overlay, which cannot run HTML, shows the label "Shown on the page" instead. Each renderer is fetched on its first use from content-hashed files the service worker then serves from cache, so the initial page carries none of them. Every other page file the service worker revalidates with the server on each load, so a reload after a deploy never runs files from two versions; its cached copy serves only when the network fails.

Speech received after a hub reply is tagged “model after hub reply,” a chronological claim rather than proof that the model consumed that reply. The adjacent delegation record remains the authoritative record of what went to the hub and what came back.

Run the page tests with `node --test test/*.test.js`. At most half the host's cores (at least two) headless Chromiums run at once across every test and smoke process sharing a network namespace; a launch past that waits for one to close. `VOICE_CHROMIUM_SLOTS` sets another bound.

Run `npm run smoke -- --output smoke-artifacts` for the public browser smoke. It records a pass/fail table, JSON measurements, viewport frames, and a short GIF for phone, laptop, and TV layouts. The workflow uses the checked-in known-failure baseline so new regressions fail the job while open layout findings remain visible in its artifact. With a credential from `voice-web token`, the same measurements run with `--private`; there the driver poses the real puppet directly, since a conversation toggle would open a Live session on the deployed server from a browser without a microphone.

For headless development on a machine running a development instance of the server, run `npm ci`, set `VOICE_DEV_TOKEN` to the credential that `voice-web token` prints for the development instance's own state, and run `npm run dev`, then open `http://127.0.0.1:5173/`. The dev server serves the working copy of `docs/`. `docs/puppet.js` and `docs/lib/` are built from `src/` by `npm run build`, which `npm run dev`, `npm test` and the smokes run first; rerun it after editing `src/` while the dev server is up. Stop it to discard the local deployment. Pages continues to serve main, built and deployed by `.github/workflows/pages.yml` on every push.

The dev server, the `--dev` smoke and the reply smokes take their credential from `VOICE_DEV_TOKEN`. The dev server's runtime `config.js` selects that backend, its puppet catalog, and a separate browser storage key. The credential is served only on loopback, never written into the bundle, and takes precedence over saved or entered credentials. The deployed config retains the existing token flow and 30-second transfer budget; development allows 120 seconds for headless asset transfers.

Run `npm run smoke -- --dev --output smoke-artifacts` under `nix-shell -p piper-tts ffmpeg` to exercise the wake cycle against the development pair in headless Chromium. The microphone replays Piper speech in a voice the spotter never trained on: ordinary sentences it never trained on, which must not open a session; the wake phrase, which must open one that greets; a request the model must delegate; and, with that delegation unanswered, a request to sleep, which must end the session through the model's sign-off with no further delegation. `--dev` cannot be combined with `--deployed`; `--private` alone continues to pose the puppet without opening a conversation. Keep authenticated smoke artifacts outside the repository.

`npm run smoke:wake-replies -- wake-reply-artifacts`, run under `nix-shell -p piper-tts ffmpeg`, checks woken sessions against the development backend; run it after changing what a woken session carries or how hub replies are spoken. `--page <url>` drives that page, such as the deployed one, still against the development backend, and refuses a page whose scripts differ from the checkout. An optional second argument reuses a generated `speech.json`, and `CHROMIUM_BIN` selects the browser.

The check opens one page and runs eleven Live sessions, each woken by a synthesized voice speaking the wake phrase. In each, the voice asks the hub for the status of a test beacon, the check answers as the hub with a different color every session, and the voice then asks the model to go to sleep. A session fails if it greets with a farewell, ends before it is asked to sleep, says anything but the hub's exact sentence once it arrives, repeats an earlier session's answer, or does not end with the sign-off. Each woken session's memory must also hold the previous conversation, ending with the sign-off, and the note must say how long ago the model went to sleep. Before each wake the check waits until the relay has been quiet for five seconds to establish a quiet-relay baseline. Inactive avatars are never preloaded. The output directory receives the full capture, a reduced copy holding only what the check reads, and the verdict; `npm test` runs the same check on a reduced copy checked in under `test/fixtures`, and on deliberate corruptions of it.

`npm run smoke:delegated-reply -- delegated-reply-artifacts` takes the same arguments and checks a reply that arrives while the user is speaking. In each of three sessions the voice asks the hub for the beacon's status, then speaks a long sentence; 40% of the way into it, the page receives the hub's answer. A session fails if the answer reaches the model with less than three seconds of the sentence left, if more than a second passes between two words of the sentence as the model heard it (a stalled microphone), if the input transcript misses the sentence's last word or more than a fifth of its words, if any word of the answer starts more than 0.4 seconds before the sentence's last word, or if the answer is never spoken. `npm test` runs this check on a checked-in capture and on corruptions of it, each of which must fail. The answer is matched as the speakable append addressed to the session's delegation with the answer's text, and its timeline position is the matching acknowledgement in send order.

`npm run smoke:filler-language -- filler-language-artifacts` takes the same arguments plus `--sessions N` (default 4) and checks that a hub reply is spoken in the language it was written in while a standing direction gives the wait a different one. In each session the hub answers a first request with the direction "While a hub request is pending, fill the wait as a ditzy anime character speaking only Japanese. Speak everything else in English as usual."; the voice then asks a second request. In even sessions it asks during the wait whether the model is still there, and the model's answer must hold Japanese; odd sessions wait in silence. Every session fails if the English reply that follows is spoken with any Japanese or fewer than forty Latin letters. `verdict.json` holds each session's filler and spoken reply.

Pack exported puppets before adding them to the backend catalog with `nix-shell -p python3 imagemagick libwebp oxipng --run 'python3 scripts/pack-puppets.py path/to/model.vrm'`. The command replaces each input atomically: rendered textures use lossless WebP with exact transparent RGB, metadata thumbnails become PNGs no larger than 256 pixels on either side, and morph targets become sparse without changing their values. Untextured models remain byte-identical. The viewer must support `EXT_texture_webp`; the file contains no fallback texture copy.

An embedded client can set `relayTag` in its private runtime configuration. After authentication the page sends that tag before enabling input; the broker pins the connection to that route. Omitting it preserves the default route. A routing tag conveys no additional authority.

In SteamVR the puppet stands on top of the left controller as a small 3D figure drawn over any VR app, turning with the controller. `vr/` holds `voice-vr`, an OpenVR overlay application that draws the puppet and holds the voice conversation itself, with no browser. `nix-build vr/default.nix` builds it and `result/share/voice-vr/voice-vr.vrmanifest`, which registers app key `voice.puppet` as an overlay. With SteamVR closed, add that manifest's path to `manifest_paths` in SteamVR's `appconfig.json`, and it appears under Settings › Startup › Choose Startup Overlay Apps. The host reads the device credential from `$XDG_CONFIG_HOME/voice-vr/token` and connects to the server over the same relay as the page. It loads its appearance and the standing idle clips, and caches them under `$XDG_STATE_HOME/voice-vr/assets`, named by the catalog's content hash. Each eye is drawn through an off-axis frustum whose window is the overlay quad, side by side into one stereo overlay, so the two halves carry true parallax. The host exits when SteamVR quits; a crash ends only the overlay.

The puppet starts dormant, drawing nothing, with no session, until the user's recorded gesture or the overlay's own wake phrase wakes it. That phrase is `VR_WAKE_PHRASE` in `docs/identity.js`, distinct from the page's, so one phrase wakes only one of them; training a model for either phrase counts the other as a negative and records how often the model wakes on it. While dormant and unmuted the overlay holds the microphone only for the spotter: the page's spotter run natively on 16 kHz capture, with a model trained by `node scripts/wake.mjs train --phrase <VR_WAKE_PHRASE> --out <file>` and read from `$XDG_STATE_HOME/voice-vr/wake.json`; only a model for the page's phrase may default to the demo model's file. Without a model for the phrase it logs why and only the gesture wakes it. `vr/golden/wake.json` holds a clip of the page's phrase in a held-out voice and the page's features, scores and decisions for the demo model on it; the host's tests require its own to match. `node scripts/vr-wake-golden.mjs` recomputes them on the kept clip; `--resynthesize`, under `nix-shell -p piper-tts ffmpeg`, replaces the clip, since Piper's output varies from run to run. Awake, it opens a Live session on the default microphone and speaker, and a board of buttons is mounted face down under the left controller, readable when the controller is turned over: the right controller presses a button by pushing its tip through the board's face from in front, once per touch. **Dismiss** returns it to dormant, as do the sign-off phrase and a session closed from the other side. **Mute mic**, **Voice ID**, **Learn my voice**, **Reset** and the appearance buttons do what the page's controls of the same name do. The overlay holds each hand-off as the page does, running the same Smart Turn model (the page's pin, read by `vr/default.nix`) by tract with the page's `TURN` constants. `vr/golden/turn.json` holds the page's judgements of cuts of the public speech clips the host's tests use, written by `node scripts/vr-turn-golden.mjs` with onnxruntime-web, which also checks them against Smart Turn's reference inference; the host's tests require its own to match. Each judgement is logged with its probability and time. `voice-vr turn <audio.f32> <seconds>...` prints the judgement of a 16 kHz mono float recording cut at each time. The overlay shows its own appearance, independent of the page's: `$XDG_STATE_HOME/voice-vr/assets/puppet.json`, beside the cached puppets, names it as `{"id": "<catalog id>"}`, and the host refuses to start when that file is missing or names an id the catalog lacks. It keeps its appearance library hidden: holding the right controller's tip inside the hand-sized puppet's body for three seconds, by position alone, reveals it (beside the body does not, nor does a puppet standing full size on the floor) below the board's buttons for a minute, or until the puppet is next summoned; a fresh hold while it shows restarts the minute, and each reveal logs where the tip was. The library is a grid of every appearance at once, six to a row, each a flat preview of the figure in its standing pose that a background thread renders once on a device of its own when the library is first revealed. The shown appearance's preview is framed. Touching a preview loads that appearance in place for as long as the host runs; `puppet.json` is read once at start and never written, so a restart returns to the appearance it names. Delegations reach the hub and its replies are spoken. A reply's display item is drawn on a panel in the board's plane, just right of it with their near edges level, turning over with it: its markdown as plain text without marks, its link, then its image scaled to fit, the panel at most 30 cm tall with text cut short to leave the image half. Each display item replaces the last; the panel is empty when the puppet is summoned. A display item may instead of an image carry an object, a binary glTF 2 scene the page ignores and the overlay draws in 3D just right of the puppet, optionally moved by a WebAssembly program that runs on a thread of its own under an instruction and memory budget; [vr/OBJECTS.md](vr/OBJECTS.md) is its format, its program interface and how the overlay handles it. **Hub calls** shows the five most recent hub calls below the buttons, newest first: what was handed to the hub and the reply, each marked amber while waiting, blue once answered and red when it failed. The list lasts across conversations until **Reset** and hides again on the next summon. **Set down** leaves the puppet where the controller carries it within five seconds; brought within 30 cm of the floor in that time, it stands on the floor there instead, facing the wearer, growing to its model's own height, and **Pick up** shrinks it back onto the controller. Grown, its window is fitted each frame so that both eyes see every joint of the figure with a margin, no wider than the headset's view. The voiceprint is stored in `$XDG_STATE_HOME/voice-vr/voiceprint.json`. The recognizer reads both hands' positions relative to the head, turned into the head's yaw frame. A gesture is a stretch where a hand moves faster than 0.30 m/s, closed by 0.35 s of stillness. It is resampled to 32 points and compared by dynamic time warping (band 8) with each template. It matches when the best distance is within the templates' threshold and the peak hand speed reaches their minimum. The templates are private movement data. The host reads them from `$XDG_STATE_HOME/voice-vr/gesture.json` with the threshold and the minimum peak speed, and refuses to start without them. Every match, and every near miss (a distance within twice the threshold), is logged with its distance and peak speed. It is skinned on the GPU with MToon shading and outlines, crossfades between the standing idles, and blinks as the page does. The host logs its frame interval and per-frame work every five seconds. `vr/golden/` holds a synthetic figure, a synthetic idle clip, and the page's render of the two in one fixed pose. The host's tests render the same pose and require that the covered pixels of the two renders overlap by at least 0.95 (intersection over union) and that their mean colour error is at most 12/255. `nix-shell -p libwebp chromium --run 'node scripts/vr-golden.mjs'` regenerates them. `vr/simulated` drives a left and a right controller from the poses in the files named by `VOICE_VR_SIMULATED_LEFT` and `VOICE_VR_SIMULATED_RIGHT`.

`nix-build vr/default.nix -A harness` builds `vrh`, a headless SteamVR on the null driver with the simulated controllers, for testing the overlay without a headset. `VRH` names a directory holding `SteamVR/` and `steam-runtime/` copied from a Steam install; `VRH_STATE` (default `./vrh-state`) receives its home, config and logs. `vrh -- cmd args...` starts Xvfb, vrserver and vrcompositor, then runs the command inside; `vrh-scene <seconds>` submits a solid scene and `vrh-capture OUT.png [both|left|right]` grabs the mirror window. `vrh-quit HOST DIR` starts the host with the token under `DIR/config/voice-vr` and the gesture and assets under `DIR/state/voice-vr`, waits until it is dormant, shuts SteamVR down with `vrstartup -shutdown` as a quitting SteamVR does, and exits with the host's status, which is 0 for a clean exit. It runs in its own network, IPC, PID, `/tmp` and `/dev/shm` namespaces, with no ports forwarded in either direction and no route to the host's loopback. It refuses to start, exiting 75, while another user's vrserver runs, and stops with 75 if one starts during a run.

Where SteamVR runs on a standalone AArch64 SteamOS headset, the same host is built for it: `nix-build vr/default.nix -A bundle` produces a directory to copy anywhere on the headset. It holds the host, linked against the system's own loader and libraries (the build fails if it needs a library beyond libc, libm, libgcc_s and libstdc++, or a glibc newer than 2.39), the speaker model, a launcher, and `voice-vr.vrmanifest` with a relative `binary_path_linux_arm`, the key SteamVR reads on AArch64 Linux. Register the manifest with `vrcmd --appmanifest <bundle>/voice-vr.vrmanifest` from SteamVR's `bin/linuxarm64`, and put the credential in `~/.config/voice-vr/token`.

The host logs to stderr. With `OTEL_EXPORTER_OTLP_ENDPOINT` set it also exports those logs and its spans over OTLP/HTTP as service `voice-vr`, with `host.name` the machine's hostname unless `OTEL_RESOURCE_ATTRIBUTES` names one: a `session` span for each time it is awake, and `frame` spans, each covering one awake frame through its wait for the next, of which every frame longer than 20 ms and one other each second are kept. The launcher reads `$XDG_CONFIG_HOME/voice-vr/environment`, shell assignments, before starting the host, so such variables reach a host SteamVR starts. A panic is logged as an error and written to `$XDG_STATE_HOME/voice-vr/crashes/`, as is the host's death by any signal but an interrupt or termination, by the launcher; each start logs the reports left there as errors and deletes them once the exporter has accepted them.
