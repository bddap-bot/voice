# voice

The phone page at <https://bddap-bot.github.io/voice/> sleeps between conversations with its microphone open, listening only for its wake phrase; while it sleeps no audio leaves the page and no session is billed. `docs/identity.js` holds the name the live model is given, the wake phrase, and how long a session may pass without speech before it ends. The wake phrase, or a tap on the puppet, opens a `gpt-live-1` WebRTC session. The page then adds a `sleep` tool to the session's backend tools, appends the name to the model's instructions, and tells it through `Context:` commentary that it was just woken, so it greets. The model ends the exchange with the `sleep` tool, and the page closes the session once playback goes quiet; a tap, the idle limit, or the provider closing the session also end it. Muting the microphone holds across sessions. The elapsed clock is visible while a session is open. There is no legacy fallback: without a usable API key the one page fails closed and says the conversation could not start.

The spotter follows openWakeWord: its melspectrogram and speech-embedding models (v0.5.1, Apache-2.0, in `docs/wake/`) run with onnxruntime-web in a worker that an audio worklet feeds 80 ms chunks, and a one-hidden-layer classifier trained for the phrase scores every chunk. A score over the model's threshold wakes the page; an episode that approaches the threshold without crossing it is logged as a `wake-miss` session event. The page asks the backend for a model with a `wake-model` relay frame and otherwise runs `docs/wake/demo.json`, trained on synthetic speech only; a `wake-model` session event records which one runs. Models trained on recordings stay on the backend host.

`node scripts/wake.mjs train [--phrase <text>]`, run under `nix-shell -p piper-tts espeak-ng flite ffmpeg`, rebuilds a model. It synthesizes the phrase with Piper (a 904-speaker voice and fourteen single-speaker voices), espeak-ng and flite, adds synthetic room reverberation and noise, trains against LibriSpeech dev-clean, generated near misses, Harvard sentences and noise, picks the threshold on validation data, and writes the recall on held-out voices and speeds and the false accepts per hour on held-out speech into the model file. Downloads are pinned by SHA-256 and cached under `node_modules/.cache/wake`. Recordings are optional: `node scripts/wake.mjs ingest <clips> --corpus <dir> --phrase <text>`, or `--ordinary` for speech without the phrase, groups clips into sessions by time and holds the latest session out for evaluation. One voice note repeating the phrase about ten times makes a session. `train --corpus <dir> --out <file>` adds those recordings and refuses to write the model inside the repository.

The browser authenticates to the server over the existing iroh link. The server exchanges the browser's SDP at `POST /v1/live/sessions`, using these documented fields: `session.model: "gpt-live-1"`, `session.instructions`, `session.audio.input.turn_detection: { type: "semantic_vad", eagerness: "high" }`, `session.audio.output.voice: "marin"`, `session.audio.output.speed: 1.25`, `session.delegation.type: "client"`, and `transport: { type: "webrtc", sdp }`. High-eagerness semantic turn detection reduces the pause before a response, while 1.25x output makes speech brisk without sacrificing clarity. The broker enforces its deadline and disconnect cleanup with `POST /v1/live/sessions/{session_id}/hangup`. The current Live WebRTC API documents this trusted-server SDP exchange rather than an ephemeral-secret field. Consequently `OPENAI_API_KEY` is read only at runtime from mode-600 `/home/bot/.secrets/openai.env`; it never enters the browser, repository, Nix store, relay diagnostics, or logs. See the official [GPT Live model page](https://developers.openai.com/api/docs/models/gpt-live-1), [WebRTC session guide](https://developers.openai.com/api/docs/guides/voice-webrtc?api=live), [hangup reference](https://developers.openai.com/api/reference/cli/resources/live/subresources/sessions/methods/hangup), and [Live conversations guide](https://developers.openai.com/api/docs/guides/live-conversations).

Browser errors and session lifecycle events travel in batches over that authenticated relay into fleet telemetry. The complete user/model transcript and separate microphone/model Opus-in-WebM streams are stored per session in private the server state through acknowledged, retrying, size-capped uploads.

Client-side delegation makes the backend agent the hub. The model emits `session.delegation.created`; the page sends the exact accumulated `session.input_transcript.delta` text plus the preceding 20 visible turns to the server, which emits a `voice-note: web ... request <id>` hub event containing an `utterance` and `context` JSON object. The hub's `voice-reply web <id> '<text>'` result returns to the model as `session.commentary.append` with `delegation_id` and `content`, so the model speaks it. See the official [backend-agent delegation guide](https://developers.openai.com/api/docs/guides/live-delegation?delegation-mode=client). While the hub works the model may say that it is waiting, but must not invent a result or use scripted filler.

At each session start, the server assembles one situation card under 600 words from the NOW notes, live jobs, pending items, open questions, and recent landings, then appends it to that session's instructions. Small questions plainly covered by the card may be answered directly. Projects, machines, schedules, plans, facts, or current state beyond it delegate by default.

The authenticated page loads its VRM puppet catalog and model bytes through the same iroh connection. Models remain on the server and are cached only in the authenticated browser. A tap on the rendered puppet wakes it or puts it to sleep: it sits with its eyes closed while asleep, stands and listens while Live is open, and sits down asleep again when Live closes. Appearance selection is persisted on the server, and required credit appears below the puppet.

Completed output sentences are classified locally into gestures and moods with quantized MiniLM embeddings. Model setup prefers WebGPU and retries with WebAssembly. On the checked-in 50-line hand-labelled evaluation set, the former keyword mood rules score 2/50 (4%) and the embedding centroids score 40/50 (80%). Run `node test/action-evaluation.js` to reproduce the comparison.

The adjacent share box accepts text, URLs, and one PNG, JPEG, GIF, or WebP image up to 8 MiB. The authenticated relay checks the image bytes, saves an accepted file in private state, and emits a `voice-note` hub event with the text and attachment path. An open Live session receives a short arrival notice.

Beside the puppet, the single page keeps a live delegation log: every turn as the model heard it; the exact hub request, reply, and round-trip timing when delegated, or a visible “model alone” tag; and the exact output transcript the model spoke. The final usage duration and estimated session cost are logged on close. This is observability, not a second interaction surface.

Hub replies can add markdown, a tappable link, or an image to the adjacent display panel. New items appear first, and image bytes travel only through the authenticated relay connection. The markdown autolinks bare URLs and renders three block kinds client-side: a ```mermaid fence as a diagram, TeX between `$…$` or `$$…$$` through KaTeX, and a ```chart fence through Chart.js, whose body is either a Chart.js configuration as JSON or CSV with a header row and one label column followed by numeric series, with `chart bar` or `chart scatter` selecting the kind. Each renderer is fetched on its first use from content-hashed files the service worker then serves from cache, so the initial page carries none of them.

Speech received after a hub reply is tagged “model after hub reply,” a chronological claim rather than proof that the model consumed that reply. The adjacent delegation record remains the authoritative record of what went to the hub and what came back.

Generate the device credential with `voice-web token` on the server. Run the page tests with `node --test test/*.test.js`.

Run `npm run smoke -- --output smoke-artifacts` for the public browser smoke. It records a pass/fail table, JSON measurements, viewport frames, and a short GIF for phone, laptop, and TV layouts. The workflow uses the checked-in known-failure baseline so new regressions fail the job while open layout findings remain visible in its artifact. A hub with an authenticated local bridge can run the same measurements with `--private`; there the driver poses the real puppet directly, since a conversation toggle would open a Live session on the deployed pair from a browser without a microphone.

For headless development on the backend host, run `npm ci` and `npm run dev`, then open `http://127.0.0.1:5173/`. The server serves the working copy of `docs/`; run `npm run build` after editing `src/`. Stop the server to discard the local deployment. Pages continues to serve main.

The host's `services.voiceDevelopment.enable` Nix option enables the separate development backend pair. The local server obtains its credential from `voice-web token` using the development instance's files. Its runtime `config.js` selects that backend, its puppet catalog, and a separate browser storage key. The credential is served only on loopback, never written into the bundle, and takes precedence over saved or entered credentials. The deployed config retains the existing token flow and 30-second transfer budget; development allows 120 seconds for headless asset transfers.

Run `npm run smoke -- --dev --output smoke-artifacts` under `nix-shell -p piper-tts ffmpeg` to exercise the wake cycle against the development pair in headless Chromium. The microphone replays Piper speech in a voice the spotter never trained on: ordinary sentences, which must not open a session; the wake phrase, which must open one that greets; and a farewell, which must close it through the `sleep` tool. `--dev` cannot be combined with `--deployed`; `--private` alone continues to pose the puppet without opening a conversation. Keep authenticated smoke artifacts outside the repository.
