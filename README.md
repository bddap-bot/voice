# voice

The phone page at <https://bddap-bot.github.io/voice/> is one continuous conversation with the bothouse hub. Its only conversation control is an on/off toggle: on opens a `gpt-live-1` WebRTC session and streams the microphone without a push-to-talk gate, local activity detector, or wake word; off closes the session. The elapsed clock is visible while on. A configurable cap defaults to 30 minutes: both the page timer and broker deadline end the session, flip the toggle off, and show the billing-guard message. There is no legacy fallback: without a usable API key the one page fails closed and says the conversation could not start.

The browser authenticates to bothouse over the existing iroh link. Bothouse—not the browser—exchanges the browser's SDP at `POST /v1/live/sessions`, using these documented fields: `session.model: "gpt-live-1"`, `session.instructions`, `session.audio.input.turn_detection: { type: "semantic_vad", eagerness: "high" }`, `session.audio.output.voice: "marin"`, `session.audio.output.speed: 1.25`, `session.delegation.type: "client"`, and `transport: { type: "webrtc", sdp }`. High-eagerness semantic turn detection reduces the pause before a response, while 1.25x output makes speech brisk without sacrificing clarity. The broker enforces its deadline and disconnect cleanup with `POST /v1/live/sessions/{session_id}/hangup`. The current Live WebRTC API documents this trusted-server SDP exchange rather than an ephemeral-secret field. Consequently `OPENAI_API_KEY` is read only at runtime from mode-600 `/home/bot/.secrets/openai.env`; it never enters the browser, repository, Nix store, relay diagnostics, or logs. See the official [GPT Live model page](https://developers.openai.com/api/docs/models/gpt-live-1), [WebRTC session guide](https://developers.openai.com/api/docs/guides/voice-webrtc?api=live), [hangup reference](https://developers.openai.com/api/reference/cli/resources/live/subresources/sessions/methods/hangup), and [Live conversations guide](https://developers.openai.com/api/docs/guides/live-conversations).

Client-side delegation makes the backend agent the hub. The model emits `session.delegation.created`; the page sends the exact accumulated `session.input_transcript.delta` text plus the preceding 20 visible turns to bothouse, which emits a `voice-note: web ... request <id>` hub event containing an `utterance` and `context` JSON object. The hub's `voice-reply web <id> '<text>'` result returns to the model as `session.commentary.append` with `delegation_id` and `content`, so the model speaks it. See the official [backend-agent delegation guide](https://developers.openai.com/api/docs/guides/live-delegation?delegation-mode=client). While the hub works the model may say that it is waiting, but must not invent a result or use scripted filler.

At each toggle-on, bothouse assembles one situation card under 600 words from the NOW notes, live jobs, pending items, open questions, and recent landings, then appends it to that session's instructions. Small questions plainly covered by the card may be answered directly. Projects, machines, schedules, plans, facts, or current state beyond it delegate by default.

The authenticated page loads its VRM puppet catalog and model bytes through the same iroh connection. Models remain on bothouse and are cached only in the authenticated browser. The rendered puppet is the sole conversation control: it sits while off, stands and listens while Live is open, and sits again when Live closes. Appearance selection is persisted on bothouse, and required credit appears below the puppet.

Beside the toggle, the single page keeps a live delegation log: every turn as the model heard it; the exact hub request, reply, and round-trip timing when delegated, or a visible “model alone” tag; and the exact output transcript the model spoke. The final usage duration and estimated session cost are logged on close. This is observability, not a second interaction surface.

Speech received after a hub reply is tagged “model after hub reply,” a chronological claim rather than proof that the model consumed that reply. The adjacent delegation record remains the authoritative record of what went to the hub and what came back.

Generate the device credential with `voice-web token` on bothouse. Run the page tests with `node --test test/*.test.js`.
