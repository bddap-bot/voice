# voice

The phone page at <https://bddap-bot.github.io/voice/> sleeps between conversations with its microphone open, listening only for its wake phrase; while it sleeps no audio leaves the page and no session is billed. `docs/identity.js` holds the name the live model is given, the wake phrase, the sign-off sentence, and how long a session may pass without speech before it ends. The wake phrase, or a tap on the puppet, opens a `gpt-live-1` WebRTC session. The page appends the name and the sign-off to the model's instructions and tells it through `Context:` commentary that it was just woken, so it greets. Every later session on the same page also starts with a memory of the page's latest earlier conversations, up to 8 KiB: their transcripts, oldest first, each marked with how long ago it ended, then a note that the model has just been woken. The model decides when a conversation is over, from a request to sleep or an implied close such as a goodbye, and ends its reply with the sign-off. When the live output transcript contains the sign-off, the page closes the session once playback goes quiet; a tap, the idle limit, or the provider closing the session also end it. Muting the microphone holds across sessions. The elapsed clock is visible while a session is open. There is no legacy fallback: without a usable API key the one page fails closed and says the conversation could not start.

The spotter follows openWakeWord: its melspectrogram and speech-embedding models (v0.5.1, Apache-2.0, in `docs/wake/`) run with onnxruntime-web in a worker that an audio worklet feeds 80 ms chunks, and a one-hidden-layer classifier trained for the phrase scores every chunk. A score over the model's threshold wakes the page; an episode that approaches the threshold without crossing it is logged as a `wake-miss` session event. The page asks the backend for its model with a `wake-model` relay frame; without a valid model for the configured phrase it reports a page error and does not listen, while a tap still opens a session. The backend keeps its model in private state.

`node scripts/wake.mjs train [--phrase <text>] [--out <file>]`, run under `nix-shell -p piper-tts espeak-ng flite ffmpeg`, rebuilds a model, by default `scripts/wake-demo.json`. It synthesizes the phrase with Piper (four multi-speaker and fourteen single-speaker voices), espeak-ng and flite, adds synthetic room reverberation and noise, and trains against LibriSpeech dev-clean, generated near misses, Harvard sentences and noise. It takes the lowest threshold that holds validation audio, including half of openWakeWord's false-positive validation features, under 0.25 false accepts per hour, then writes into the model file the recall on held-out voices, speakers and speeds and the false accepts per hour on held-out audio: LibriSpeech test-clean, the other half of those features, and Harvard sentences and near misses in held-out voices. The voice models, LibriSpeech archives and validation features are checked against SHA-256 digests, and downloads are cached under `node_modules/.cache/wake`. `--acav <megabytes>` adds that much of openWakeWord's ACAV100M features as negatives; they are licensed CC BY-NC-SA 4.0, so such a model must be written outside the repository. Without them, the demo model false-accepts about 35 times an hour on the held-out validation features; it is a fixture for the tests, not a model to deploy. Recordings are optional: `node scripts/wake.mjs ingest <clips> --corpus <dir> --phrase <text>`, or `--ordinary` for speech without the phrase, groups clips into sessions by time and holds the latest quarter of the sessions, at least one, out for evaluation. One voice note repeating the phrase about ten times makes a session. `train --corpus <dir> --out <file>` adds those recordings, keeps their decoded audio and features under `<dir>/cache`, and refuses to write the model inside the repository.

**Learn my voice**, on the expanded controls card, makes a voiceprint between conversations: talk normally for about ten seconds while the button shows progress; tapping it again stops. The page keeps only the mean of 192-number speaker embeddings from 3D-Speaker's ERes2Net model (trained on VoxCeleb, Apache-2.0), computed in the browser and kept in its local storage; the learning audio is neither sent nor stored. In later conversations the microphone passes through this filter before the Live session. **Voice ID on**, on the card once a voice is learned, switches the filter off and on, also during a conversation; off sends the microphone itself, with no added delay, and keeps the voiceprint. The choice stays on the device with the voiceprint; learning a voice turns it on, and forgetting the voice stops filtering at once. Speech is held from its start and scored after about a second; matching speech is sent from its first sound, so no word is clipped, but it arrives about a second late plus scoring time, and each reply starts that much later. Other speech is dropped. Sent speech is rescored every second, so a different voice that follows without a pause is cut off within about two seconds. The filter tells voices apart but does not authenticate: a similar voice or a recording gets through. The model, about 26 MB, is fetched from a pinned revision on first use, checked against its SHA-256 digest, and cached. If it fails, learning stops without a voiceprint, or the conversation continues unfiltered with the status "speaker filter off, hearing everyone"; the next conversation tries again. Without a voiceprint, after **Forget my voice** or **Forget token**, or after the pinned model changes, the next conversation sends everything it hears. The idle limit counts only speech that was sent. The session's microphone recording, described below, still holds everything the microphone heard, and each score is logged as a `speaker-score` session event with its time span.

The page's server, `voice-web`, is not part of this repository and is not published. The page reaches it over iroh with ALPN `voice-web/1`, and its `voice-web token` command prints the device credential the page asks for. The page's iroh transport in `docs/relay/` is a copy of the bddap-bot/botq browser build at commit `3868c6d` (iroh 1.0.3); updating it replaces both files. The server exchanges the browser's SDP at `POST /v1/live/sessions`, using these documented fields: `session.model: "gpt-live-1"`, `session.instructions`, `session.input` with the earlier turns and wake marker of a woken session, `session.audio.output.voice: "marin"`, `session.delegation.type: "client"`, and `transport: { type: "webrtc", sdp }`. The broker enforces its deadline and disconnect cleanup with `POST /v1/live/sessions/{session_id}/hangup`. The current Live WebRTC API documents this trusted-server SDP exchange rather than an ephemeral-secret field. Consequently `OPENAI_API_KEY` is read only at runtime from a mode-600 server-side key file; it never enters the browser, repository, Nix store, relay diagnostics, or logs. See the official [GPT Live model page](https://developers.openai.com/api/docs/models/gpt-live-1), [WebRTC session guide](https://developers.openai.com/api/docs/guides/voice-webrtc?api=live), [hangup reference](https://developers.openai.com/api/reference/cli/resources/live/subresources/sessions/methods/hangup), and [Live conversations guide](https://developers.openai.com/api/docs/guides/live-conversations).

Browser errors and session lifecycle events travel in batches over that authenticated relay into telemetry. The `live-config-*` session records capture only provider-reported model IDs, delegation type/target/model, and tool names from session and delegation events and the SDP answer; absent fields remain absent, and instructions and transcript text are excluded from these configuration records. The complete user/model transcript and separate microphone/model Opus-in-WebM streams are stored per session in private server state through acknowledged, retrying, size-capped uploads.

Client delegation makes the backend agent the hub. The model emits `session.delegation.created`; the page sends the exact `session.input_transcript.delta` text heard since the previous delegation, plus up to 20 earlier visible turns, to the server, which emits a `voice-note: web ... request <id>` hub event containing an `utterance` and `context` JSON object. A hub reply is text to speak; the page appends it as `session.commentary.append` with the delegation's ID. While a delegation awaits its reply, if the model neither speaks nor delegates within three seconds of the latest user transcript text, the page itself delegates the text heard since the previous delegation, and the hub's reply or failure is appended with a null delegation ID. The page appends a reply as soon as it arrives, even while the user is still speaking; the model speaks it at its next turn, after the user finishes, as it would answer anything else it hears. Each append holds at most 500 tokens, so longer text arrives as several appends; a reply reaches the model if the session is still open and the model has not signed off. The hub may send several replies to one request, such as a status and then its result, or a series of slides. A later reply waits while the model is still speaking an earlier hub reply; once that reply is spoken and playback has been quiet for 1.5 seconds, the next is appended and its display item appears. If the user speaks while the model is speaking a hub reply, the later replies still waiting are dropped, each logged as a `hub-reply-dropped` session event. A spoken reply that reaches the page while Live is asleep is acknowledged as unspoken, so the hub learns it was not heard. An answer to a question in a hub reply is delegated without being asked; a change of subject is handled as a new request. A request to sleep is never delegated: the model signs off even while a delegation awaits its reply. See the official [client delegation guide](https://developers.openai.com/api/docs/guides/live-delegation?delegation-mode=client). Each delegated turn is also traced: the page sends one OTLP span per stage (`hear`, `decide`, `delegate`, `await-speech`) in a `spans` frame, and the delegation request carries its `delegate` span as a W3C `traceparent` so the server's stages join the trace. A turn the model answers without delegating is traced as `hear` and `reply`.

A turn's `reply` span runs from the last transcribed speech to the start of reply audio. Each avatar load is also traced in the `spans` frame: an `avatar-load` span carrying `avatar.file` and `user_agent.original`, with one child span per stage — `bytes` (transfer or cache read, with `puppet.bytes`), `parse`, `select`, `fit`, `render` (the first GPU-completed frame), `clips` (the remaining wait for clip motions, fetched once per page alongside the first model) and `animate`; the avatar catalog is fetched once per connection, not per load. The server exports page spans as OTLP with resource `service.name=page` and `host.name=voice` (a fixed label). Its collector's file exporter writes OTLP-JSON lines grouped by `host.name`, so page spans land in `otlp-voice.jsonl` in the collector's output directory. From that directory, this prints per-stage p50/p90 milliseconds over completed loads, by device class (phone, tablet, tv or desktop, from `user_agent.original`):

```sh
jq -rn -f scripts/avatar-load.jq otlp-voice.jsonl*
```

A hub reply may also carry standing instructions: how the model should behave from then on, such as how to fill a wait. Appended beside a reply, instructions cut off its speech, so the page waits until the reply is spoken, playback has been quiet for 1.5 seconds, and no other hub reply is waiting; then it sends them as their own `session.instructions.append` with a null delegation ID, which changes behavior without being spoken. A reply of instructions alone ends the delegation's wait silently. Past 90% context use, as reported by `session.usage.updated`, Live moves to a fresh engine that knows only the startup instructions, so the page appends the latest standing instructions again. The server puts them in the startup instructions of later sessions.

At each session start, the server assembles one situation card under 600 words from the NOW notes, live jobs, pending items, open questions, and recent landings, then appends it to that session's instructions. Small questions plainly covered by the card may be answered directly. Projects, machines, schedules, plans, facts, or current state beyond it delegate by default.

The authenticated page loads its VRM puppet catalog through the iroh connection. The page fetches the active avatar as soon as it connects and shows it seated and asleep; other avatars are fetched only when chosen in the appearance selector. Wake detection and signalling do not wait for the avatar to load. Until it appears, the stage shows a tap-to-talk prompt. Models remain on the server and are cached only in the authenticated browser. A tap on the rendered puppet wakes it or puts it to sleep: it sits with its eyes closed while asleep, stands and listens while Live is open, and sits down asleep again when Live closes. While Live is open, the page keeps the screen on with a Screen Wake Lock where the browser supports it, and takes the lock again when the page returns from the background; asleep, it holds none and the device's screen timeout applies. Appearance selection is persisted on the server, and required credit appears below the puppet.

Completed output sentences are classified locally into gestures and moods with quantized MiniLM embeddings. Model setup prefers WebGPU and retries with WebAssembly. On the checked-in 50-line hand-labelled evaluation set, the former keyword mood rules score 2/50 (4%) and the embedding centroids score 40/50 (80%). Run `node test/action-evaluation.js` to reproduce the comparison.

The adjacent share box accepts text, URLs, and one PNG, JPEG, GIF, or WebP image up to 8 MiB. The authenticated relay checks the image bytes, saves an accepted file in private state, and emits a `voice-note` hub event with the text and attachment path. An open Live session receives a short arrival notice.

Beside the puppet, the single page keeps a live delegation log: every turn as the model heard it; the exact hub request, reply, and round-trip timing when delegated, or a visible “model alone” tag; and the exact output transcript the model spoke. The final usage duration and estimated session cost are logged on close. This is observability, not a second interaction surface.

A phone may discard the page while it is in the background and reload it when the user returns. While the page is hidden, including as it unloads, its tab's session storage holds the delegation log, about the newest quarter million characters, and whether Live was open; the copy is deleted whenever the page is in view. On reload the log reappears and remains the memory of earlier conversations; a conversation that was open is marked ended at the last save. If Live was open and less than the idle limit has passed since that save, it opens a new session once reconnected. The display panel and cost lines are not kept, and nothing survives a crash while the page is in view or closing the app.

Hub replies can add markdown, a tappable link, or an image to the adjacent display panel; a reply may carry only a display item. New items appear first, and image bytes travel inside the reply, only over the authenticated relay connection. The markdown autolinks bare URLs and renders three block kinds client-side: a ```mermaid fence as a diagram, TeX between `$…$` or `$$…$$` through KaTeX, and a ```chart fence through Chart.js, whose body is either a Chart.js configuration as JSON or CSV with a header row and one label column followed by numeric series, with `chart bar` or `chart scatter` selecting the kind. Each renderer is fetched on its first use from content-hashed files the service worker then serves from cache, so the initial page carries none of them. Every other page file the service worker revalidates with the server on each load, so a reload after a deploy never runs files from two versions; its cached copy serves only when the network fails.

Speech received after a hub reply is tagged “model after hub reply,” a chronological claim rather than proof that the model consumed that reply. The adjacent delegation record remains the authoritative record of what went to the hub and what came back.

Run the page tests with `node --test test/*.test.js`.

Run `npm run smoke -- --output smoke-artifacts` for the public browser smoke. It records a pass/fail table, JSON measurements, viewport frames, and a short GIF for phone, laptop, and TV layouts. The workflow uses the checked-in known-failure baseline so new regressions fail the job while open layout findings remain visible in its artifact. With a credential from `voice-web token`, the same measurements run with `--private`; there the driver poses the real puppet directly, since a conversation toggle would open a Live session on the deployed server from a browser without a microphone.

For headless development on a machine running a development instance of the server, run `npm ci` and `npm run dev`, then open `http://127.0.0.1:5173/`. The dev server serves the working copy of `docs/`; run `npm run build` after editing `src/`. Stop it to discard the local deployment. Pages continues to serve main.

The dev server obtains its credential from the development instance's `voice-web token`. Its runtime `config.js` selects that backend, its puppet catalog, and a separate browser storage key. The credential is served only on loopback, never written into the bundle, and takes precedence over saved or entered credentials. The deployed config retains the existing token flow and 30-second transfer budget; development allows 120 seconds for headless asset transfers.

Run `npm run smoke -- --dev --output smoke-artifacts` under `nix-shell -p piper-tts ffmpeg` to exercise the wake cycle against the development pair in headless Chromium. The microphone replays Piper speech in a voice the spotter never trained on: ordinary sentences it never trained on, which must not open a session; the wake phrase, which must open one that greets; a request the model must delegate; and, with that delegation unanswered, a request to sleep, which must end the session through the model's sign-off with no further delegation. `--dev` cannot be combined with `--deployed`; `--private` alone continues to pose the puppet without opening a conversation. Keep authenticated smoke artifacts outside the repository.

`npm run smoke:wake-replies -- wake-reply-artifacts`, run under `nix-shell -p piper-tts ffmpeg`, checks woken sessions against the development backend; run it after changing what a woken session carries or how hub replies are spoken. `--page <url>` drives that page, such as the deployed one, still against the development backend, and refuses a page whose scripts differ from the checkout. An optional second argument reuses a generated `speech.json`, and `CHROMIUM_BIN` selects the browser.

The check opens one page and runs eleven Live sessions, each woken by a synthesized voice speaking the wake phrase. In each, the voice asks the hub for the status of a test beacon, the check answers as the hub with a different color every session, and the voice then asks the model to go to sleep. From the second session on, the voice first asks what color the beacon was before the model went to sleep. A session fails if it greets with a farewell, ends before it is asked to sleep, sends that question to the hub, names any color but the previous session's, says anything but the hub's exact sentence once it arrives, or does not end with the sign-off. Each woken session's memory must also hold the previous conversation, ending with the sign-off, and the note must say how long ago the model went to sleep. Before each wake the check waits until the relay has been quiet for five seconds to establish a quiet-relay baseline. Inactive avatars are never preloaded. The output directory receives the full capture, a reduced copy holding only what the check reads, and the verdict; `npm test` runs the same check on a reduced copy checked in under `test/fixtures`, and on deliberate corruptions of it.

`npm run smoke:delegated-reply -- delegated-reply-artifacts` takes the same arguments and checks a reply that arrives while the user is speaking. In each of three sessions the voice asks the hub for the beacon's status, then speaks a long sentence; 40% of the way into it, the page receives the hub's answer. A session fails if the answer reaches the model with less than three seconds of the sentence left, if more than a second passes between two words of the sentence as the model heard it (a stalled microphone), if the input transcript misses the sentence's last word or more than a fifth of its words, if any word of the answer starts more than 0.4 seconds before the sentence's last word, or if the answer is never spoken. `npm test` runs this check on a checked-in capture, on corruptions of it, and on a capture in which the model spoke the answer over the sentence, which must fail.

Pack exported puppets before adding them to the backend catalog with `nix-shell -p python3 imagemagick libwebp oxipng --run 'python3 scripts/pack-puppets.py path/to/model.vrm'`. The command replaces each input atomically: rendered textures use lossless WebP with exact transparent RGB, metadata thumbnails become PNGs no larger than 256 pixels on either side, and morph targets become sparse without changing their values. Untextured models remain byte-identical. The viewer must support `EXT_texture_webp`; the file contains no fallback texture copy.

An embedded client can set `relayTag` in its private runtime configuration. After authentication the page sends that tag before enabling input; the broker pins the connection to that route. Omitting it preserves the default route. A routing tag conveys no additional authority.
